# CivicRouteAD cleanup notes

This package received a careful **file/data cleanup only**. Application source logic was not intentionally changed.

## Removed
- `frontend/node_modules/`: installed dependencies (recreated by `start.bat` or `npm install` in `frontend/`). The lockfile is retained so npm can reproduce the dependency tree.
- Python `__pycache__` folders and `.pyc` bytecode caches.
- `backend/runs/`: generated outputs from earlier analysis runs. The app recreates this directory and its outputs when a scenario or upload is processed.
- A saved test/public report and its uploaded evidence video. `backend/data/civic_reports.json` was reset to an empty list so the ZIP does not carry a local user submission, its contact/location metadata, or an absolute Windows file path.
- The duplicate root-level `yolov8n.pt`; the identical copy in `backend/yolov8n.pt` is retained and used by the standard launcher.
- `test_carto.png`, which had no references in the source/configuration files.

## Preserved
- All application source files and the frontend package manifest/lockfile.
- The built frontend in `frontend/dist/` as a ready-to-serve fallback.
- All three bundled sample scenario videos and GPX tracks.
- The backend YOLO model weights, API routes, test scripts, README, and project documentation.

## First run
1. Extract the ZIP.
2. Ensure Python 3.10+ and Node.js LTS are installed and available in PATH.
3. Double-click `start.bat`. The script installs missing Python/frontend packages and builds the frontend; internet is required for first-time package installation.

The original uploaded ZIP was not modified.


## Generated frontend bundle

`frontend/dist` is generated by `npm run build`; it should not be treated as source code. The complete source ZIP omits stale generated assets so `start.bat` rebuilds from `frontend/src`. The launcher validates the `advanced-map-proxy-20261010` marker and fails rather than silently serving an old bundle. Stop any older process using port 8000 before launching the updated project.
