Keep the terminal open. The first launch needs internet access for dependencies and the frontend build. Then open `http://localhost:8000`.

## Analysis Lab: uploaded video

1. Open **Analysis lab** and select the user's MP4.
2. A GPX/CSV file is optional for video-only detection; it is required for synchronized route geolocation.
3. The backend analyzes video frames in the background and returns timestamped detections.
4. Red polygons are rendered only when the model produces a valid segmentation polygon; otherwise the overlay uses the detection bounding box.
5. `POTHOLE` labels are reserved for explicit pothole classes (RDD D40 or a dedicated pothole model). D00/D10/D20 classes are mapped to road cracks. OpenCV candidates are `POSSIBLE ROAD ANOMALY`, not confirmed potholes.

### Optional dedicated segmentation weights

If you have a licensed/verified `pothole_seg.pt` checkpoint, place it at `backend/models/pothole_seg.pt` or set `CIVICROUTE_POTHOLE_SEG_MODEL` to its path before starting the server. Check `/api/health` for `pothole_seg_model_loaded`. This checkout did not contain that checkpoint. Without it, masks cannot be generated by that model. Do not download an arbitrary checkpoint without confirming its provenance, task architecture, and license.

## Advanced: area intelligence

1. Open **Advanced**.
2. Click **Use my current location**, and allow browser location access, or enter latitude and longitude manually.
3. The default radius is 1 km; choose the issue category and click **Analyze selected area**.
4. Street-style, satellite, and 3D view modes are available. 3D building extrusions depend on the external vector style exposing building-height data; a 2D Leaflet fallback is used if the MapLibre CDN is unavailable.
5. Mapillary street-level imagery and native object detections are queried securely through the backend server using the `MAPILLARY_ACCESS_TOKEN` configured in `.env`.
6. OpenStreetMap road tags and stored resident reports are shown as separate context/report types, not as AI detections.
7. Candidate records are unverified until staff review. Exports are available as CSV and GeoJSON. Staff must sign in through the existing Staff Workspace to change persisted candidate review status.

## Mapillary Access Token Setup Guide

To enable street-level imagery discovery and native object detections:

1. **Obtain a Mapillary Developer Token**:
   - Register or sign in at [Mapillary Developer Portal](https://www.mapillary.com/developer).
   - Under **Developer Applications**, click **Register Application**.
   - Set the application name (e.g. `CivicRouteAD-Local`) and select **Read** permissions.
   - Generate and copy your **Client Token** (format: `MLY|...`).

2. **Configure Backend Environment**:
   - In `Civic_RouteAD/` (or `Civic_RouteAD/backend/`), copy `.env.example` to `.env` if not already present.
   - Set:
     ```env
     MAPILLARY_ACCESS_TOKEN=MLY|your_token_here
     ```
   - Restart the CivicRouteAD server (`.\start.bat`).

3. **Security & Authentication Protocol**:
   - The token is read server-side only and never sent to browser bundles, git repositories, or logged in cleartext.
   - Requests use standard HTTP header authentication: `Authorization: OAuth <token>`.
   - On invalid/expired token responses (HTTP 401/403), the server halts immediately without making repetitive tiled requests, reporting status `authentication_failed`.
   - Diagnostic status endpoint: `GET /api/infrastructure/mapillary/status` provides live token validation without leaking secrets.

## Important limitations

- A 1 km radius defines the geographic query area, not guaranteed imagery coverage.
- Satellite imagery in this version is a basemap/context layer; it does not run automatic pothole segmentation on satellite pixels.
- Street imagery may be historical; its capture date is shown when the API supplies it. The source-image coordinate is not an exact surveyed coordinate for the pothole.
- Dashcam camera-to-ground projection is approximate unless the camera is calibrated and tested against ground-truth points.
- Models can miss true potholes or misclassify curbs/shadows. Use annotated examples and labelled positive/negative frames to measure precision and recall before operational deployment.
- The older RDD checkpoint and general YOLO model are not substitutes for a verified pothole-segmentation checkpoint. This package contains `yolov8n.pt` only; it does not contain `yolov8s_best.pt` or `pothole_seg.pt`.

## Recent API, Map, and Video Pipeline Fixes

1. **Mapillary Authentication & Truthful Statuses**:
   - Upstream Mapillary calls are proxied through `/api/infrastructure/mapillary/scan`.
   - Access token is loaded securely on the backend from `MAPILLARY_ACCESS_TOKEN`.
   - Auth errors immediately stop requests and return truthful status `authentication_failed` instead of repeating tiled bounding boxes or fabricating detections.
   - Statuses returned: `not_configured`, `authentication_failed`, `provider_unavailable`, `completed_no_coverage`, `completed_no_detections`, `completed_with_candidates`.

2. **OpenStreetMap / Overpass CORS & Timeout Elimination**:
   - Eliminated direct browser-to-Overpass calls; all context queries go through `/api/infrastructure/osm-context`.
   - Upstream queries are bounded by radius and category with a strict 10-second timeout.
   - In-memory cache with 15-minute TTL prevents duplicate requests and upstream rate limits.
   - Multi-endpoint fallback across `overpass-api.de`, `kumi.systems`, and `maps.mail.ru`.
   - UI surfaces `OpenStreetMap context temporarily unavailable` with an interactive "Retry OSM" action.

3. **MapLibre Sprite Errors & Null Extrusion Prevention**:
   - Pre-registered neutral 24x24 canvas glyphs for the 10 missing sprite icons (`swimming_pool`, `sports_centre`, `office`, `gate`, `lift_gate`, `bollard`, `atm`, `motorcycle_parking`, `reservoir`, `bicycle_parking`) plus resolution variants on `load` and `style.load`.
   - Fallback `styleimagemissing` event handles any additional uncatalogued icons.
   - Coalesced `fill-extrusion-height` and `fill-extrusion-base` paint properties to `0` when null, resolving the runtime error `Expected value to be of type number, but found null instead`.

4. **Analysis Lab Video Detection Pipeline**:
   - Increased outline hold window in `interpolateDetectionBoxes` and `interpolateTelemetryAtTime` to smoothly bridge 1–2 dropped frames without lagging or persisting onto empty road.
   - Added live frame inference trigger on video seek/pause when footage is loaded.
   - Enforced strict color and labeling separation: Red `#dc2626` outline + `POTHOLE 0.xx` is strictly reserved for genuine model D40 detections. Heuristic OpenCV candidates are rendered in slate grey `#94a3b8` with label `POSSIBLE ROAD ANOMALY 0.xx` to prevent misidentifying curbs and road markings as potholes.

## Diagnose remaining pothole outlines

Open `http://localhost:8000/api/health` and verify that `pothole_seg_model_loaded` or `road_damage_model_loaded` is `true`. If neither is loaded, the Advanced local-AI imagery scan will return no confirmed pothole candidates. In the browser Network tab, inspect the live inference/frame response or the completed run's `telemetry.json`: confirm that detection objects contain `type: "pothole_damage"`, numeric `bbox` values or a valid `polygon` with `has_mask: true`, and the corresponding frame timestamp. The Advanced map console errors and Analysis Lab video overlay are separate rendering/data paths.
